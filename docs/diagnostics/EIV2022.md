# EIV2022 — UnknownDocumentType (Order-X)

| | |
|---|---|
| **Category** | `UnmappedElement` |
| **Default severity** | `Warning` |
| **Fallback** | The document is read as an order |

## What it means

All three Order-X documents — the order, the order change and the order response — share one root element.
`ExchangedDocument/TypeCode` is the only thing that says which of them you are holding, and this document
declared a code that is none of the three.

It is the only place in this library where what a document *is* has to be read out of a value rather than
off its root element, which is why a code nobody recognises is worth saying out loud.

| Code | Document |
|---|---|
| `220` | Order |
| `230` | Order change |
| `231` | Order response |

## Why it is not fatal

The content is still an order: the parties, the lines, the quantities and the prices are all where they
belong, and refusing the whole document over one element would lose all of it. So it is read as an order and
this says the assumption was made.

## Example

```
EIV2022  Warning  UnmappedElement  Type code '105' is not an Order-X order (220), order change (230) or
    order response (231). at /rsm:SCRDMCCBDACIOMessageStructure/rsm:ExchangedDocument/ram:TypeCode (line 22)
```

## What to do

Ask the sender which of the three they meant. A code from the wider UNTDID 1001 list usually means their
system writes a general document type where Order-X expects one of its three.

```csharp
services.AddEInvoicing(o => o.OnCode("EIV2022", DiagnosticAction.Escalate));
```
