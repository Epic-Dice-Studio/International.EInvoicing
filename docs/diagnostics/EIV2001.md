# EIV2001 — InvalidValue

| | |
|---|---|
| **Category** | `InvalidValue` |
| **Default severity** | `Warning` |
| **Fallback** | The field keeps its raw text; the typed value is `null` and `IsRawOnly` is `true` |

## What it means

An element carried text that could not be converted to the type its syntax declares: a date that is not a
date, an amount with a comma as decimal separator, a quantity that is not numeric.

The document still parses. Only this one field is affected, and its text is preserved.

## Example

```xml
<cbc:TaxExclusiveAmount currencyID="EUR">1 234,56</cbc:TaxExclusiveAmount>
```

```
EIV2001  Warning  InvalidValue  The value '1 234,56' could not be read as an amount.
    at /Invoice/cac:LegalMonetaryTotal/cbc:TaxExclusiveAmount (BT-109)
    fallback  raw text preserved; Value is null
```

## How to handle it

```csharp
if (invoice.TaxExclusiveAmount.IsRawOnly)
{
    // The text is still there — repair it, reject the document, or route it for manual review.
    string asSent = invoice.TaxExclusiveAmount.Raw!;
}
```

Whether this is fatal is a business decision. An amount you cannot read is usually fatal; a malformed
optional note usually is not — so escalate per business term rather than globally:

```csharp
services.AddEInvoicing(o => o.OnDiagnostic(d =>
    d.Code == "EIV2001" && d.BusinessTerm?.StartsWith("BT-1") == true
        ? DiagnosticAction.Fail
        : DiagnosticAction.Keep));
```

## How to fix the document

The sender is emitting a value that does not match its declared type. Amounts use a period as decimal
separator, no thousands separator and no scientific notation; dates follow the format their attribute
declares. See `docs/standards/` for the syntax concerned.
