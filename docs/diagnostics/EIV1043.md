# EIV1043 — UnsupportedProfile

| | |
|---|---|
| **Category** | `UnsupportedProfile` |
| **Default severity** | `Error` |
| **Fallback** | Generic reading of the parent profile |

## What it means

The profile identifier is recognised — this library knows the profile exists and knows its name — but no
implementation is registered for it. This is stricter than [EIV1042](EIV1042.md): there, the identifier was
unknown and might be private; here, we know we are failing to do something the standard defines.

## Example

```
EIV1043  Error  UnsupportedProfile  at /rsm:CrossIndustryInvoice/rsm:ExchangedDocumentContext (BT-24)
    expected  an implemented profile
    found     urn:cen.eu:en16931:2017#conformant#urn:factur-x.eu:1p0:extended
    fallback  parsed as EN 16931 CII; EXTENDED-only elements kept in ExtensionData
```

## What was and was not done

The document parsed and the EN 16931 core is populated. Elements belonging only to the unsupported profile are
preserved in `ExtensionData` — nothing was dropped — but they are not typed, and the profile's rules did not
run. `ValidationReport.IsComplete` is false and states which rule sets were skipped.

## How to fix it

Check the support matrix in the README: the profile may be planned rather than absent. You can implement it in
your own code today (`docs/recipes/add-a-profile.md`), or use the raw values from `ExtensionData` for the few
fields you actually need (`docs/guides/raw-values.md`).

## Why this is an error by default

Because silence here would be dishonest: the caller believes they are handling a standard profile. Lower it
deliberately if your process genuinely only needs the core:

```csharp
services.AddEInvoicing(o => o.OnCode("EIV1043", DiagnosticAction.Keep));
```
