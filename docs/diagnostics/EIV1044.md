# EIV1044 — UnsupportedEdition

| | |
|---|---|
| **Category** | `UnsupportedProfile` |
| **Default severity** | `Error` |
| **Fallback** | Read against the edition this library implements; anything else kept in extension data |

## What it means

The document declares an edition of EN 16931 other than the one this library implements. The standard has
been revised: CEN published **EN 16931-1:2026** in May 2026 and formally withdrew the 2017 edition, which
stays compliant only for a migration period. The revision adds business terms for the 2030 digital reporting
requirements and is not backward compatible.

This library implements **EN 16931-1:2017**, which is the edition every published artefact and every national
CIUS is currently written against.

This is a different situation from [EIV1042](EIV1042.md), where the identifier is unknown, and from
[EIV1043](EIV1043.md), where a known profile has no implementation registered. Here the document *is* an
EN 16931 invoice; it is written to a version of the model we do not carry yet.

## Example

```
EIV1044  Error  UnsupportedProfile  at /Invoice/cbc:CustomizationID (BT-24)
    expected  EN 16931-1:2017
    found     EN 16931-1:2026
    fallback  read as EN 16931; terms this edition does not have are kept in extension data
```

## What was and was not done

The document parsed. Every business term the two editions share was read normally, with its raw text and
attributes. Elements the 2017 model has no field for went to `ExtensionData` — nothing was dropped — and the
rules that ran were the 2017 ones, so `ValidationReport.IsComplete` is false and names what did not run.

## How to fix it

Three options, in increasing order of effort:

1. **Ask for the edition you can process.** Until the ecosystem migrates, most senders can still issue 2017.
2. **Read what you need from the extension data.** See [raw values](../guides/raw-values.md).
3. **Register the newer edition yourself.** A profile, a mapping and a rule set can all be added from your own
   code — see [add a profile](../recipes/add-a-profile.md) — and a registered profile wins over the built-in
   fallback. The rule artefacts for the 2026 edition are not published yet; when they are, load them with
   `AddRulesFromFile(...)`.

## Why this is an error by default

Because a caller who believes they read a 2026 invoice, and in fact read the terms it happens to share with
2017, will act on incomplete data without knowing it. Lower it deliberately when your process only needs the
core:

```csharp
services.AddEInvoicing(o => o.OnCode("EIV1044", DiagnosticAction.Keep));
```
