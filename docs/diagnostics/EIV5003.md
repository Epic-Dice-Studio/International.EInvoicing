# EIV5003 — UnsupportedEncoding

| | |
|---|---|
| **Category** | `Safety` |
| **Default severity** | `Warning` |
| **Fallback** | Decoded as UTF-8, or as ISO-8859-1 when the bytes are not valid UTF-8. |

## What it means

The document declares an encoding this library does not decode. It decodes UTF-8, UTF-16, ISO-8859-1 and
US-ASCII, plus whatever a byte-order mark names.

Everything else — Windows-1252, Shift-JIS, the ISO-8859 family beyond `-1` — needs the
`System.Text.Encoding.CodePages` package, which is a dependency every user would carry for a case almost none
of them have. So the library says what it assumed instead of pretending.

## Example

```
EIV5003  Warning  Safety  The document declares encoding 'windows-1252', which this library does not decode.
    found: windows-1252
    fallback: decoded as UTF-8, or as ISO-8859-1 when the bytes are not valid UTF-8
```

Windows-1252 is the common one, and the fallback is close: it differs from ISO-8859-1 only in `0x80`–`0x9F`,
which holds the curly quotes, the em dash and the euro sign. A document with none of those decodes correctly.

## How to handle it

If you receive these regularly, decode the bytes yourself and hand the library the text:

```csharp
Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);   // System.Text.Encoding.CodePages

string text = Encoding.GetEncoding("windows-1252").GetString(bytes);
DocumentResult result = library.Read(text);
```

`Read(string)` skips the decoding step entirely, so nothing second-guesses you.
