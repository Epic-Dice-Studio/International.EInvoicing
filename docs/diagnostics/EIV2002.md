# EIV2002 — UnsupportedDateFormat

| | |
|---|---|
| **Category** | `InvalidValue` |
| **Default severity** | `Info` |
| **Fallback** | The field keeps its raw text and its format code; the typed value is `null` |

## What it means

A date declared a **valid** UNTDID 2379 format code that this library does not convert to a typed value.
`102` (`CCYYMMDD`) and ISO dates are converted; partial formats such as `610` (`CCYYMM`) or `616` (week)
are not, because there is no honest way to turn a month or a week into a single date.

This is not a defect in the document. Severity is `Info` for exactly that reason.

## Example

```xml
<ram:DateTimeString format="610">202608</ram:DateTimeString>
```

```
EIV2002  Info  InvalidValue  Date format code '610' is valid but not converted to a typed value.
    at /rsm:CrossIndustryInvoice/.../ram:OccurrenceDateTime (BT-72)
    fallback  raw text and format code preserved; Value is null
```

## How to handle it

Everything you need is on the field:

```csharp
DateField period = invoice.DeliveryDate;
if (period.IsRawOnly && period.FormatCode == "610")
{
    var month = DateOnly.ParseExact(period.Raw!, "yyyyMM", CultureInfo.InvariantCulture);
}
```

Writing the document back is lossless: an untouched field is re-emitted from its raw text with its original
format code.

## Why the library does not guess

Converting `202608` to the first of the month would produce a date the sender never wrote, which would then
propagate into totals, due dates and reports. Reporting the fact and preserving the text leaves the decision
where it belongs.
