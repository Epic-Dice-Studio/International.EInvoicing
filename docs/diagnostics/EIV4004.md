# EIV4004 — TooMany

| | |
|---|---|
| **Category** | `Safety` |
| **Default severity** | `Error` |
| **Fallback** | The first *n* were read. The rest were not. |

## What it means

The document carried more invoice lines than `DocumentLimits.MaxDocumentLines` (100 000 by default), or more
attached documents than `DocumentLimits.MaxAttachmentCount` (100). Reading stopped at the limit.

It is an `Error` rather than a warning on purpose: **the invoice in your hands is not the invoice that was
sent**. Its lines will not add up to its totals, and a `BR-CO-10` failure downstream would be a confusing way
to find that out.

## Example

```
EIV4004  Error  Safety  The document carries more than 100000 invoice lines; the rest was not read.
    found: more than 100000 invoice lines
    fallback: the first 100000 were read; the rest were not
```

## Common causes

| What happened | What to do |
|---|---|
| A genuine consolidated invoice from a large supplier | Raise the limit for that source |
| A generated document with a runaway loop | Tell the sender; do not raise the limit |
| A deliberately oversized document | This is what the limit is for |

## How to change the limit

```csharp
services.AddEInvoicing(o => o.UseLimits(new DocumentLimits
{
    MaxDocumentLines = 500_000,
    MaxAttachmentCount = 500,
}));
```

`0` on either means no limit.

## How not to handle it

Do not suppress this one and carry on. A truncated invoice that reads cleanly is worse than one that fails:

```csharp
o.OnCode("EIV4004", DiagnosticAction.Suppress);   // hides that lines are missing. Don't.
```
