# EIV5001 — MalformedXml

| | |
|---|---|
| **Category** | `Safety` |
| **Default severity** | `Fatal` |
| **Fallback** | None. This is the one case where no document is produced. |

## What it means

The bytes handed to the reader are not well-formed XML, or they broke a limit that exists to stop hostile
input: a prohibited DTD, an entity expansion, a document beyond `DocumentLimits.MaxDocumentCharacters`.

Unlike every other diagnostic, there is nothing to fall back to — a reader cannot map a document it cannot
parse. `ParseResult.IsUsable` is false and `Value` is null.

## Example

```
EIV5001  Fatal  Safety  The document is not well-formed XML: For security reasons DTD is prohibited in this
    XML document. at line 2, position 10
```

## Common causes

| What happened | What to do |
|---|---|
| Truncated transfer | Re-fetch the document; check the sender's transport |
| A DTD or external entity | The document is trying to reach outside itself. Treat it as hostile, not as a bug in this library. |
| Document larger than the limit | Raise `DocumentLimits.MaxDocumentCharacters` **only** if you trust the source |
| A PDF or a ZIP passed to an XML reader | Detect the container first; a Factur-X PDF goes through the PDF reader |

## How to handle it

```csharp
ParseResult<EInvoice> result = reader.Read(stream);
if (!result.IsUsable)
{
    // Nothing was produced. The diagnostics say why, and where.
    foreach (Diagnostic diagnostic in result.Diagnostics)
    {
        logger.LogError("{Code} {Message} at {Location}", diagnostic.Code, diagnostic.Message, diagnostic.Location);
    }
}
```

## Why it cannot be downgraded

A policy may raise a diagnostic's severity, never lower this one into usability: there is no document to
return. `DiagnosticAction.Suppress` on `EIV5001` hides the explanation without producing an invoice, which is
strictly worse — do not.
