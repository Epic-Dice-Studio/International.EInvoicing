# EIV4002 — PayloadTooLarge

| | |
|---|---|
| **Category** | `Safety` |
| **Default severity** | `Fatal` |
| **Fallback** | None. The attachment is refused, not truncated. |

## What it means

The invoice embedded in the PDF is larger than `DocumentLimits.MaxAttachmentBytes` and was not decoded.

Invoices arrive from third parties, so a compressed attachment that expands to something enormous is a
plausible attack, not merely an unusual document. The limit exists to make that harmless, and a refused
attachment is the limit working.

## Example

```
EIV4002  Fatal  Safety  The embedded invoice is larger than the 67108864 byte limit and was not decoded.
```

## Raising the limit

Only for sources you trust:

```csharp
services.AddEInvoicing(o => o.UseLimits(new DocumentLimits
{
    MaxAttachmentBytes = 256L * 1024 * 1024,
}));
```

The default is 64 MB, which is already far beyond any legitimate CII payload — a large invoice with hundreds
of lines is measured in hundreds of kilobytes. An invoice near the limit deserves suspicion before it
deserves a bigger limit.
