# EIV5005 — MalformedXml (ZUGFeRD 1.0)

| | |
|---|---|
| **Category** | `Safety` |
| **Default severity** | `Fatal` |
| **Fallback** | None. No document is produced. |

## What it means

The bytes handed to the ZUGFeRD 1.0 reader are not well-formed XML, or they broke a limit that exists to
stop hostile input. It is [EIV5001](EIV5001.md) for ZUGFeRD 1.0, under its own code so a caller can tell
which reader refused.

## Reading an archive

This is the code an archive migration meets most often, and usually not because anything is hostile.
Documents extracted from 2013-era PDF containers are frequently truncated, doubly-encoded, or saved with a
byte-order mark in the middle of the file. A run over an archive should expect some of these and record
which files produced them rather than stopping.

```csharp
ParseResult<EInvoice> result = library.Zugferd1.Read(bytes);

if (!result.IsUsable)
{
    log.CouldNotRead(path, result.Diagnostics);
    continue;
}
```

## Common causes

| What happened | What to do |
|---|---|
| Truncated extraction from a PDF/A-3 container | Re-extract; the attachment stream may have been cut |
| A DTD or external entity | The document is trying to reach outside itself. Treat it as hostile. |
| Document larger than the limit | Raise `DocumentLimits.MaxDocumentCharacters` **only** if you trust the source |
