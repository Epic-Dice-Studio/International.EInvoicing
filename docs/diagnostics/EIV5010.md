# EIV5010 — UnrecognisedDocument

| | |
|---|---|
| **Category** | `Safety` |
| **Default severity** | `Fatal` |
| **Fallback** | None. Nothing was read. |

## What it means

`EInvoicing.Read` looked at the document and found nothing it recognises. It is well-formed XML — a malformed
document reports [EIV5001](EIV5001.md) instead — but its root element belongs to none of the syntaxes this
library reads.

Detection is by root element and namespace, never by file name or extension, because senders name files
whatever they like.

## What it recognises

| Root namespace | Read as |
|---|---|
| `…:ubl:schema:xsd:Invoice-2` and `…:CreditNote-2` | UBL 2.1 |
| `…:CrossIndustryInvoice:100` | UN/CEFACT CII |
| `…:CrossDomainAcknowledgementAndResponse:100` | a lifecycle status message |
| bytes beginning `%PDF-` | a PDF, opened if a PDF reader is registered |

## Common causes

| What happened | What to do |
|---|---|
| An older UBL version, or a different UBL document type | Only Invoice and CreditNote are read today. |
| A national format that is not EN 16931 — FatturaPA, Facturae, KSeF | Not supported yet; see the support matrix. |
| An envelope wrapping the invoice | Unwrap it first. Transport envelopes are out of scope. |
| A ZIP, or a PDF whose bytes were mangled in transit | Check what actually arrived. |

## Handling it

```csharp
DocumentResult result = einvoicing.Read(stream);

if (!result.IsUsable && result.Diagnostics.Any(d => d.Code == "EIV5010"))
{
    // Not something this library reads. Route it wherever unrecognised documents go.
}
```

If you know what the document is and the library simply does not read it yet, you can register your own
reader — see `docs/recipes/add-a-format.md`.
