# EIV4010 — ProfileIsNotAnEn16931Invoice

| | |
|---|---|
| **Category** | `UnsupportedProfile` |
| **Default severity** | `Warning` |
| **Fallback** | None needed — the document is read in full |

## What it means

The document declares Factur-X **MINIMUM** or **BASIC WL**. Both are legitimate Factur-X profiles, both read
perfectly well, and neither is a complete invoice under EN 16931: they carry header data and totals without
the lines the norm requires.

Nothing went wrong. You are being told because the legal usefulness of such a document is narrow, and because
a system that treats it as an ordinary invoice will later find fields it expected to be there missing.

## Example

```
EIV4010  Warning  UnsupportedProfile  Profile 'Factur-X MINIMUM' carries header data and totals but not
    the lines EN 16931 requires of an invoice. (BT-24)
    fallback  read in full; the document is not an EN 16931 invoice
```

## What you can rely on

| Profile | Header and totals | VAT breakdown | Invoice lines |
|---|---|---|---|
| MINIMUM | yes | no | no |
| BASIC WL | yes | yes | no |
| BASIC and above | yes | yes | yes |

```csharp
if (result.Diagnostics.Any(d => d.Code == "EIV4010"))
{
    // Do not expect invoice.Lines to contain anything.
}
```

## If this is unacceptable to you

Many processes cannot use an invoice without lines. Say so explicitly rather than discovering it downstream:

```csharp
services.AddEInvoicing(o => o.OnCode("EIV4010", DiagnosticAction.Fail));
```

## Why the library does not refuse them outright

Because they are valid documents that a partner is entitled to send, and because refusing to read something
is not the same as telling you what it is. Choosing a profile is a business decision — see
`docs/standards/facturx.md`.
