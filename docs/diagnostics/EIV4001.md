# EIV4001 — MissingPayload

| | |
|---|---|
| **Category** | `Container` |
| **Default severity** | `Fatal` |
| **Fallback** | None. A PDF without an embedded invoice has nothing structured to read. |

## What it means

A PDF arrived, but it carries no invoice payload — none of `factur-x.xml`, `zugferd-invoice.xml`,
`ZUGFeRD-invoice.xml` or `xrechnung.xml` is embedded in it.

The same code is reported when a PDF arrives and no `IPdfAttachmentReader` is registered: the library can see
it is a PDF and cannot look inside it.

## Example

```
EIV4001  Fatal  Container  The PDF carries no embedded invoice: none of factur-x.xml,
    zugferd-invoice.xml, ZUGFeRD-invoice.xml, xrechnung.xml was found.
    expected  factur-x.xml
    found     no embedded invoice
```

## What to check

| | |
|---|---|
| The sender emailed a printed invoice | It is a PDF, not a hybrid invoice. There is nothing to extract; ask for a structured document. |
| No PDF reader registered | Reference `International.EInvoicing.FacturX.PdfSharp` and call `AddFacturXPdfSharp()`, or supply your own `IPdfAttachmentReader`. The diagnostic's `Expected` says which case you are in. |
| The payload is attached but not as an associated file | Some producers attach the XML without declaring it. This library looks in both the associated-files array and the EmbeddedFiles name tree, so this is rare — report it if you meet one. |
| The attachment exceeds your size limit | That is [EIV4002](EIV4002.md), not this. |

## Handling it

```csharp
ParseResult<EInvoice> result = reader.Read(stream);
if (!result.IsUsable && result.Diagnostics.Any(d => d.Code == "EIV4001"))
{
    // Route to whatever you do with unstructured invoices — a person, or OCR.
}
```
