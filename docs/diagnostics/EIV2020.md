# EIV2020 — UnmappedElement

| | |
|---|---|
| **Category** | `UnmappedElement` |
| **Default severity** | `Info` |
| **Fallback** | The element is kept verbatim in `ExtensionData` and written back unchanged |

## What it means

The document carried an element the canonical model does not describe — a national extension, a partner's
private field, an element of a profile beyond EN 16931. Nothing was dropped: the element is preserved exactly
as it appeared, including its namespace and children.

Severity is `Info` because this is normal. Real invoices carry more than the semantic model does.

## Example

```xml
<acme:PurchaseOrderScan xmlns:acme="urn:acme:invoice:1p0">PO-42</acme:PurchaseOrderScan>
```

```
EIV2020  Info  UnmappedElement  Element 'PurchaseOrderScan' is not part of the canonical model and was kept
    as extension data. at /Invoice/acme:PurchaseOrderScan (line 31)
    fallback  kept verbatim as extension data
```

## Reaching the content

```csharp
foreach (ExtensionElement element in invoice.Extensions.Named("urn:acme:invoice:1p0", "PurchaseOrderScan"))
{
    string xml = element.Xml;      // the element exactly as it arrived
    var parsed = XElement.Parse(xml);
}
```

Extension data hangs off every node, not only the document: a line, a party or an item keeps its own
unmapped elements.

## When to worry

Turn it up when you expect to understand everything you receive:

```csharp
services.AddEInvoicing(o => o.OnCode("EIV2020", DiagnosticAction.Escalate));
```

A burst of these on documents from one sender usually means they use a profile you have not registered — see
[EIV1042](EIV1042.md) and [EIV1043](EIV1043.md), which will be reported alongside.
